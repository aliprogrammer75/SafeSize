# Dedicated account QA

Explicit opt-in workflow, never triggered by ordinary pushes or pull requests. If dispatch is unavailable on the unmerged branch, an explicit change to integration/account_qa_trigger.txt with commit marker [run-account-qa] can start it after the secret is configured. Use a new WordPress **Subscriber** named `safesize-qa-ci`, with no personal data. Set its password in the repository Actions secret `SAFESIZE_QA_PASSWORD` yourself; never commit or paste it into chat. Run "SafeSize dedicated account and real push QA" on `unified-web-mobile`. The workflow refuses an absent secret and non-QA workspace records; uses independent desktop Chromium and Android Chrome logins. It writes only synthetic data to the dedicated test account, checks real API workspace round trips, stale revision (409), invalid nonce (403), Replay bookmark transport, and AES-GCM encrypted synthetic journal transport. It also attempts actual PushManager subscription, real server VAPID delivery, and Android notification shade while Chrome is backgrounded. It removes only the random QA push device afterwards. Only a sanitized report is uploaded. This is not a full UI auto-sync or replay-resume test; native journal migration, physical phone and real account data are outside scope. A missing or failed subscription is a failure, not a simulated pass. The dedicated account must not be used for any real data. Tests leave synthetic workspace, replay and journal data for future QA; remove the test account manually when no longer needed.
