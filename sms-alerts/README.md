# هشدار پیامکی SafeSize

<div dir="rtl">

ثبت هشدار از چارت SafeSize، رصد پیوستهٔ قیمت <bdi>Last</bdi> یا <bdi>Mark</bdi> عمومی Bitunix و ارسال یک‌باره از ملی‌پیامک. سرویس باید روی سروری اجرا شود که بعد از بستن اپ روشن می‌ماند. برای هر نصب سرور، یک گیرنده از تنظیمات همان سرور تعیین می‌شود.

## اجرا در حالت آزمایشی

با <bdi>Node.js 24</bdi> وارد پوشهٔ <bdi>sms-alerts</bdi> شوید. فایل <bdi>.env.example</bdi> را به <bdi>.env</bdi> کپی کنید. یک توکن با <bdi>openssl rand -hex 32</bdi> بسازید و آن را در <bdi>ALERT_API_TOKEN</bdi> قرار دهید. مقدار <bdi>SMS_MODE=dry-run</bdi> کافی است و فیلدهای ملی‌پیامک می‌توانند خالی بمانند.

</div>

```sh
npm test
npm start
```

<div dir="rtl">

برای اجرای پایدار از سرویس سیستم یا تصویر Docker همین پوشه استفاده کنید. فایل SQLite را در فضای پایدار نگه دارید و فقط یک نمونه به آن متصل کنید. روی سرور، یک پراکسی HTTPS معتبر به پورت محلی <bdi>8080</bdi> وصل کنید تا اپ بتواند به آن دسترسی داشته باشد.

</div>

```sh
docker build -t safesize-sms .
docker run -d --name safesize-sms --restart unless-stopped \
  --env-file .env -e HOST=0.0.0.0 -p 127.0.0.1:8080:8080 \
  -v safesize-sms-data:/app/data safesize-sms
```

<div dir="rtl">

در SafeSize وارد <b>رصد بازار ← هشدار پیامکی ← اتصال سرور پیامک</b> شوید و آدرس HTTPS و توکن همین سرویس را ثبت کنید. سپس در چارت، در فرم هشدار قیمت، «پیامک از سرور» را انتخاب کنید. فهرست رصد بازار وضعیت «در انتظار قیمت»، «آزمایش موفق»، «پذیرفته‌شده توسط ملی‌پیامک» یا نتیجهٔ خطا را نشان می‌دهد.

## بعد از فعال شدن پنل ملی‌پیامک

1. نام کاربری پنل و کلید وب‌سرویس را به‌ترتیب در <bdi>MELIPAYAMAK_USERNAME</bdi> و <bdi>MELIPAYAMAK_API_KEY</bdi> روی سرور قرار دهید. <bdi>SMS_TO</bdi> شمارهٔ موبایل گیرنده است.
2. برای ارسال عادی، شمارهٔ فرستندهٔ مجاز پنل را در <bdi>MELIPAYAMAK_FROM</bdi> وارد کنید. برای ارسال از الگوی خدماتی، شناسهٔ الگوی تأییدشده را در <bdi>MELIPAYAMAK_BODY_ID</bdi> بگذارید. ترتیب متغیرهای الگو باید نماد، نوع قیمت، سطح هشدار و قیمت لحظهٔ فعال‌شدن باشد. الگوی نمونه روی پنل ایجاد نشده است.
3. اگر وب‌سرویس برای حساب IP مجاز می‌خواهد، IP خروجی سرور را در پنل ثبت کنید. سپس <bdi>SMS_MODE=live</bdi> تنظیم کنید و سرویس را با همان فضای داده دوباره اجرا کنید.
4. یک هشدار جدید بسازید و نتیجه را از صفحهٔ رصد بازار و گزارش پنل بررسی کنید. حالت هر هشدار هنگام ثبت ذخیره می‌شود. بنابراین هشدارهای ثبت‌شده در حالت آزمایشی حتی پس از تغییر تنظیمات، آزمایشی باقی می‌مانند.

رویداد فقط یک‌بار صف‌بندی می‌شود. در صورت پاسخ مبهم یا قطع ارتباط هنگام ارسال، نتیجه «نامشخص» ثبت می‌شود تا ارسال خودکار تکراری انجام نشود. «پذیرفته‌شده» یعنی ملی‌پیامک شناسهٔ ارسال برگردانده است. تحویل نهایی به گوشی را از گزارش پنل بررسی کنید.

- [مستندات ارسال الگوی خدماتی](https://www.melipayamak.com/api/sendbybasenumber2/)
